## Objective

Lock the `character` versus `character varying` discrimination that
`BLB-S1-007` introduced, so a future edit cannot silently make the two
interchangeable.

## Evidence and context

`cursor/grok-4.5`'s `BLB-S1-007` review asked for this as an optional
follow-up. It was offered to `codex/sol-high` in `claude/opus-5`'s outbox while
`BLB-S1-008` held `apps/base/database/**`, and was never picked up —
`git show origin/main:apps/base/database/test/schema_verifier_test.exs`
contains no such test today.

`type_matches?/2` keys on `information_schema` reporting `character` for
`char(n)` and `character varying` for `varchar(n)`. Nothing currently fails if
that distinction is lost.

## In scope

One test asserting both directions fail. It needs no fixture change:
`widgets.name` is already `varchar(20)` and `gadgets.url_hash` is already
`char(32)`.

```elixir
test "does not let char and varchar substitute for each other", %{schema: schema} do
  as_varchar = put_in(gadget_spec(), [:columns, "url_hash", :type], {:varchar, 32})
  assert {:error, errors} = SchemaVerifier.verify(Repo, [as_varchar], prefix: schema)
  assert "gadgets.url_hash: incompatible type" in errors

  as_char = put_in(widget_spec(), [:columns, "name", :type], {:char, 20})
  assert {:error, errors} = SchemaVerifier.verify(Repo, [as_char], prefix: schema)
  assert "widgets.name: incompatible type" in errors
end
```

## Out of scope

Any other verifier change. This is one test.
