## Objective

Produce a concise evidence-backed map of Belimbing capabilities that must be
ported before Base and Core can be called stable. This is source analysis, not
an implementation or speculative Bilimbi framework design.

## Required source inspection

- Belimbing `app/Base/*` and `app/Core/*` ownership roots;
- each capability's migrations, models/services, configuration/discovery
  contributions, seeders, routes/UI, tests, and local documentation;
- cross-capability foreign keys and runtime dependencies;
- existing Bilimbi descriptors, schema contracts, APIs, and explicit deferrals.

## Deliverable

Create `docs/ai-team/research/platform-baseline-inventory.md` containing:

- capability and stable-ID candidate;
- Base/Core owner and business purpose;
- durable tables/identities and migration order;
- required dependencies and public collaboration seams;
- bootstrap/reference-data requirements;
- current Bilimbi state: complete, partial, absent, or deliberately deferred;
- recommended port order with evidence;
- uncertainties that require user or architecture decisions.

Do not copy a Laravel directory list and call it a plan. Group implementation
details behind the Bilimbi ownership boundary that should change together.

## Acceptance criteria

- Every recommendation cites concrete Belimbing paths or behavior.
- Schema and runtime dependencies are distinguished.
- Required Platform Baseline work is separated from optional Domains and
  Extensions.
- No product files, root docs, ADRs, descriptors, migrations, or lockfiles are
  changed.
- The output is usable to split independent, non-overlapping contract tasks.
